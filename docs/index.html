serviceMonitor

A monitor that watches containers over the network. Agents register over TCP, then send a UDP heartbeat every 3 seconds. When one goes quiet for 9 seconds, the monitor logs it as down.

Silence per agent

Seconds since each agent's last heartbeat. A healthy agent resets every 3 seconds; a line that climbs past 9 seconds is an outage.

How it works

Three Python agents and one monitor, each in its own container on a Docker bridge network.

  1. An agent connects over TCP and sends REGISTER agent1. The monitor answers ACK and starts a watcher thread for it.
  2. Every 3 seconds the agent sends a UDP datagram, HB agent1. Each one resets the watcher's clock.
  3. If 9 seconds pass with no heartbeat, the watcher writes a CRITICAL DOWN line to the audit log.
  4. When heartbeats come back, the agent is marked active again and a new watcher starts.
